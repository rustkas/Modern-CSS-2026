# Глава 13. Программируемый цвет и алгоритмические палитры

> После перехода веб-платформы на перцептивные цветовые пространства (см. главу 12) следующий этап развития CSS связан уже не с самим представлением цвета, а с его вычислением. Современный браузер способен смешивать цвета, модифицировать отдельные компоненты палитры, автоматически адаптировать оформление под тему интерфейса и постепенно брать на себя задачи, которые ещё несколько лет назад выполнялись препроцессорами или JavaScript.

Главная идея современной CSS-архитектуры заключается в том, что разработчик описывает **правила получения цвета**, а не хранит десятки заранее рассчитанных оттенков.

---

## 13.1 Цвет как вычисляемое значение

### От статической палитры к вычисляемой системе

До появления CSS Color Level 4 большинство проектов представляло палитру как набор статических переменных:

```css
:root {
  --primary-50: #eff6ff;
  --primary-100: #dbeafe;
  --primary-200: #bfdbfe;
  --primary-300: #93c5fd;
  --primary-400: #60a5fa;
  --primary-500: #3b82f6;
  --primary-600: #2563eb;
  --primary-700: #1d4ed8;
  --primary-800: #1e40af;
  --primary-900: #1e3a8a;
  --primary-950: #172554;
}
```

Такой подход плохо масштабируется:

```text
Проблемы статической палитры:
  ↓
Десятки переменных на каждый цвет
  ↓
Рассинхронизация оттенков
  ↓
Сложность поддержки нескольких тем
  ↓
Огромный объём работы при смене бренда
```

### Современная модель

Современный CSS предлагает противоположную модель. Вместо хранения десятков производных оттенков приложение хранит лишь несколько исходных цветов, а остальные вычисляются непосредственно браузером.

```css
:root {
  /* Всего несколько исходных цветов */
  --brand: oklch(65% 0.22 255);
  --surface: light-dark(white, #1a1a1a);
  --text: light-dark(#1a1a1a, white);
  
  /* Остальное — вычисляется */
  --brand-hover: color-mix(in oklch, var(--brand), white 15%);
  --brand-active: color-mix(in oklch, var(--brand), black 15%);
  --brand-subtle: color-mix(in oklch, var(--brand), transparent 85%);
}
```

**Это радикально упрощает поддержку дизайн-систем.**

```text
Традиционный подход:
  ↓
Храним все оттенки
  ↓
Изменяем каждый вручную
  ↓
Сложно поддерживать
  ↓
Современный подход:
  ↓
Храним базовые цвета
  ↓
Вычисляем производные
  ↓
Просто поддерживать
```

## 13.2 `color-mix()`: декларативное смешивание цветов

### Первый инструмент программируемого цвета

Функция `color-mix()` стала первым инструментом, превратившим CSS в язык работы с цветом.

```css
.button {
  background: var(--brand);
  
  &:hover {
    background: color-mix(
      in oklch,
      var(--brand) 85%,
      white
    );
  }
  
  &:active {
    background: color-mix(
      in oklch,
      var(--brand) 85%,
      black
    );
  }
  
  &:disabled {
    background: color-mix(
      in oklch,
      var(--brand) 50%,
      gray
    );
  }
}
```

### Современные рекомендации

**1. Выполняйте смешивание преимущественно в `oklch` или `oklab`**

```css
/* ✅ Рекомендуется */
background: color-mix(in oklch, var(--brand), white 15%);
background: color-mix(in oklab, var(--brand), white 15%);

/* ❌ Устаревает */
background: color-mix(in srgb, var(--brand), white 15%);
```

**2. Используйте `srgb` только при необходимости совместимости**

```css
/* Только для существующей палитры, где важен точный цвет */
background: color-mix(in srgb, #2563eb, white 15%);
```

**3. Всегда явно указывайте цветовое пространство**

```css
/* ✅ Явно указано пространство */
background: color-mix(in oklch, red, blue);

/* ❌ Не указано — зависит от браузера */
background: color-mix(red, blue);
```

### Почему пространство важно

Одни и те же два цвета дают различные промежуточные оттенки в разных пространствах:

```text
color-mix(in srgb, red, blue)
  ↓
Середина между красным и синим в sRGB
  ↓
Тёмный, неестественный оттенок
  ↓
color-mix(in oklch, red, blue)
  ↓
Середина между красным и синим в OKLCH
  ↓
Визуально правильный пурпурный
```

## 13.3 Relative Color Syntax

### Изменение одного цвета

Если `color-mix()` объединяет несколько цветов, то Relative Color Syntax изменяет один существующий цвет.

```css
:root {
  --brand: oklch(65% 0.22 255);
  
  /* Изменяем светлоту */
  --brand-light: oklch(
    from var(--brand)
    calc(l + 0.15)
    c
    h
  );
  
  --brand-dark: oklch(
    from var(--brand)
    calc(l - 0.15)
    c
    h
  );
  
  /* Изменяем насыщенность */
  --brand-muted: oklch(
    from var(--brand)
    l
    calc(c / 2)
    h
  );
  
  /* Изменяем оттенок */
  --brand-complement: oklch(
    from var(--brand)
    l
    c
    calc(h + 180)
  );
}
```

### Как это работает

CSS автоматически:

```text
1. Извлекает компоненты цвета
   ↓
2. Преобразует их в нужное пространство
   ↓
3. Позволяет изменить отдельные каналы
   ↓
4. Собирает новый цвет
```

### Практическое применение

```css
:root {
  --brand: oklch(65% 0.22 255);
  
  /* Состояния через изменение светлоты */
  --brand-hover: oklch(
    from var(--brand)
    calc(l + 0.05)
    c
    h
  );
  
  --brand-active: oklch(
    from var(--brand)
    calc(l - 0.05)
    c
    h
  );
  
  /* Семантические варианты */
  --brand-subtle: oklch(
    from var(--brand)
    calc(l + 0.25)
    calc(c / 3)
    h
  );
  
  --brand-intense: oklch(
    from var(--brand)
    l
    calc(c * 1.3)
    h
  );
}
```

**Это превращает палитру в набор математических правил.**

### Когда использовать Relative Color Syntax

На практике Relative Color Syntax чаще всего используется для изменения:

| Операция | Пример |
|----------|--------|
| Светлота | `oklch(from var(--color) calc(l + 0.1) c h)` |
| Насыщенность | `oklch(from var(--color) l calc(c / 2) h)` |
| Оттенок | `oklch(from var(--color) l c calc(h + 30))` |
| Прозрачность | `oklch(from var(--color) l c h / 0.5)` |

## 13.4 Алгоритмические палитры

### От статической к алгоритмической палитре

До появления современных цветовых функций библиотеки дизайна содержали десятки заранее подготовленных оттенков.

Сегодня всё чаще используется другой подход:

```text
Brand Color
  ↓
Hover (светлее на 10%)
  ↓
Pressed (темнее на 10%)
  ↓
Surface (светлее на 25%, меньше насыщенность)
  ↓
Outline (насыщенность 50%)
  ↓
Subtle (прозрачность 85%)
```

### Реализация алгоритмической палитры

```css
:root {
  /* Базовый цвет */
  --brand: oklch(65% 0.22 255);
  
  /* === Производные цвета === */
  
  /* Состояния */
  --brand-hover: oklch(
    from var(--brand)
    calc(l + 0.06)
    c
    h
  );
  
  --brand-pressed: oklch(
    from var(--brand)
    calc(l - 0.06)
    c
    h
  );
  
  /* Поверхности */
  --brand-surface: oklch(
    from var(--brand)
    calc(l + 0.30)
    calc(c / 4)
    h
  );
  
  --brand-surface-strong: oklch(
    from var(--brand)
    calc(l + 0.20)
    calc(c / 2)
    h
  );
  
  /* Акценты */
  --brand-outline: oklch(
    from var(--brand)
    calc(l + 0.10)
    calc(c * 0.6)
    h
  );
  
  --brand-subtle: color-mix(
    in oklch,
    var(--brand),
    transparent 85%
  );
  
  /* Контрастные варианты */
  --brand-contrast: oklch(
    from var(--brand)
    calc(l * 0.4)
    c
    h
  );
}
```

### Преимущества алгоритмической палитры

```text
Статическая палитра:
  ↓
50+ переменных
  ↓
Изменение бренда → пересчёт всех оттенков
  ↓
Рассинхронизация
  ↓
Алгоритмическая палитра:
  ↓
5-10 переменных
  ↓
Изменение бренда → автоматическая адаптация
  ↓
Все оттенки согласованы
```

**Достаточно изменить один базовый цвет.**

```css
/* Смена бренда — меняем один цвет */
:root {
  --brand: oklch(70% 0.18 350); /* Было: oklch(65% 0.22 255) */
}

/* Все производные вычисляются автоматически */
```

## 13.5 Адаптация под тему интерфейса

### `light-dark()` — разделение логики и темы

Одной из важнейших возможностей CSS Color стало разделение логики выбора цвета и самой темы оформления.

Функция `light-dark()` позволяет описать обе версии интерфейса одной декларацией:

```css
:root {
  --surface: light-dark(
    white,           /* Светлая тема */
    #1a1a1a          /* Тёмная тема */
  );
  
  --text: light-dark(
    #1a1a1a,         /* Светлая тема */
    #f0f0f0          /* Тёмная тема */
  );
  
  --border: light-dark(
    #e2e8f0,         /* Светлая тема */
    #334155          /* Тёмная тема */
  );
}
```

### Совместная работа с `color-scheme`

Совместно с `color-scheme` браузер автоматически переключает оформление между светлой и тёмной темами:

```css
:root {
  color-scheme: light dark;
}

@media (prefers-color-scheme: dark) {
  :root {
    color-scheme: dark;
  }
}
```

**Исчезает необходимость дублировать множество правил внутри `@media (prefers-color-scheme)`.**

```css
/* ❌ Устаревает — дублирование правил */
@media (prefers-color-scheme: dark) {
  .card {
    background: #1a1a1a;
    color: #f0f0f0;
    border-color: #334155;
  }
}

@media (prefers-color-scheme: light) {
  .card {
    background: white;
    color: #1a1a1a;
    border-color: #e2e8f0;
  }
}

/* ✅ Современный подход — одна декларация */
.card {
  background: light-dark(white, #1a1a1a);
  color: light-dark(#1a1a1a, #f0f0f0);
  border-color: light-dark(#e2e8f0, #334155);
}
```

## 13.6 Автоматический выбор контрастного цвета

### `contrast-color()` — доступность на уровне CSS

Следующим шагом развития CSS стала функция `contrast-color()`. Она позволяет получить цвет текста, обеспечивающий максимальный контраст относительно заданного фона.

```css
.text-on-accent {
  background: var(--accent);
  color: contrast-color(var(--accent));
}

/* С явным указанием вариантов */
.text-on-accent {
  color: contrast-color(
    var(--accent),
    white,  /* Первый вариант */
    black   /* Второй вариант */
  );
}
```

### Практическое применение

```css
:root {
  --accent: oklch(65% 0.22 255);
}

.button {
  background: var(--accent);
  color: contrast-color(var(--accent));
  
  &:hover {
    background: color-mix(in oklch, var(--accent), white 10%);
    color: contrast-color(
      color-mix(in oklch, var(--accent), white 10%)
    );
  }
}

.card {
  background: var(--surface);
  
  &.accent {
    background: var(--accent);
    color: contrast-color(var(--accent));
  }
}
```

### Статус и ограничения

**На момент подготовки книги:**

- Функция уже поддерживается всеми современными движками
- Относится к категории **Baseline Newly Available**
- Для проектов с длительным жизненным циклом рекомендуется предусматривать резервный вариант

```css
@supports (color: contrast-color(white)) {
  .text-on-accent {
    color: contrast-color(var(--accent));
  }
}

@supports not (color: contrast-color(white)) {
  .text-on-accent {
    /* Резервный вариант */
    color: white;
    text-shadow: 0 1px 2px rgba(0,0,0,0.3);
  }
}
```

### Важное ограничение

Для некоторых цветов средней светлоты оба варианта (чёрный и белый) могут давать недостаточный контраст для мелкого текста.

```text
Цвет средней светлоты
  ↓
Белый текст → недостаточный контраст
  ↓
Чёрный текст → недостаточный контраст
  ↓
Нужен другой цвет (например, тёмно-серый)
```

**Автоматический выбор цвета не заменяет проверку требований WCAG.**

```css
/* Рекомендуется явно проверять контраст */
.text-on-accent {
  color: contrast-color(var(--accent));
  
  /* Для мелкого текста — дополнительная проверка */
  @supports (font-size: 0.75rem) {
    color: contrast-color(
      var(--accent),
      white,
      black,
      #333333
    );
  }
}
```

## 13.7 Архитектура современных дизайн-систем

### Поток вычислений

Современные дизайн-системы постепенно уходят от хранения больших таблиц цветов.

Типичная архитектура выглядит следующим образом:

```text
Brand Color
      │
      ▼
Relative Color Syntax
(изменение каналов)
      │
      ▼
color-mix()
(смешивание с белым/чёрным)
      │
      ▼
light-dark()
(адаптация к теме)
      │
      ▼
contrast-color()
(выбор текста)
      │
      ▼
Финальный интерфейс
```

### Полный пример

```css
@layer tokens {
  :root {
    /* === 1. Базовые цвета === */
    --brand: oklch(65% 0.22 255);
    --surface: light-dark(white, #1a1a1a);
    --text: light-dark(#1a1a1a, white);
    
    /* === 2. Производные через Relative Color Syntax === */
    --brand-hover: oklch(
      from var(--brand)
      calc(l + 0.06)
      c
      h
    );
    
    --brand-active: oklch(
      from var(--brand)
      calc(l - 0.06)
      c
      h
    );
    
    --brand-muted: oklch(
      from var(--brand)
      l
      calc(c / 2)
      h
    );
    
    /* === 3. Поверхности через color-mix() === */
    --surface-raised: color-mix(
      in oklch,
      var(--surface),
      light-dark(black, white) 5%
    );
    
    --surface-floating: color-mix(
      in oklch,
      var(--surface),
      light-dark(black, white) 10%
    );
    
    /* === 4. Акценты с автоматической темой === */
    --accent: light-dark(
      var(--brand),
      var(--brand-hover)
    );
    
    --accent-surface: color-mix(
      in oklch,
      var(--accent),
      var(--surface) 80%
    );
    
    /* === 5. Автоматический контраст === */
    --text-on-accent: contrast-color(var(--accent));
    --text-on-surface: var(--text);
  }
}
```

### Роли функций в системе

```text
Relative Color Syntax
  ↓
изменяет один цвет
  ↓
color-mix()
  ↓
объединяет несколько цветов
  ↓
light-dark()
  ↓
адаптирует палитру к теме
  ↓
contrast-color()
  ↓
обеспечивает читаемость
```

**В результате CSS начинает напоминать небольшой декларативный язык вычислений.**

## 13.8 Практические рекомендации

### Архитектурные правила

Современная практика разработки постепенно пришла к нескольким устойчивым правилам.

**1. Используйте OKLCH как основное рабочее пространство**

```css
/* ✅ Рекомендуется */
:root {
  --brand: oklch(65% 0.22 255);
}

/* ❌ Устаревает */
:root {
  --brand: #2563eb;
}
```

**2. Не храните десятки оттенков одного цвета — вычисляйте их**

```css
/* ✅ Рекомендуется */
--brand: oklch(65% 0.22 255);
--brand-light: oklch(from var(--brand) calc(l + 0.15) c h);

/* ❌ Устаревает */
--brand-50: #eff6ff;
--brand-100: #dbeafe;
/* ... и так до 950 */
```

**3. Различайте `color-mix()` и Relative Color Syntax — это разные операции, а не конкурирующие способы решить одну задачу**

```css
/* Меняет только светлоту, насыщенность сохраняется */
--hover-relative: oklch(from var(--brand) calc(l + 0.05) c h);

/* Смещает и светлоту, и насыщенность к нейтральному белому — 
   визуально более "пастельный", выцветший результат */
--hover-mixed: color-mix(in oklch, var(--brand), white 15%);
```

Эти два подхода **не взаимозаменяемы**, а решают разные задачи:

* **Relative Color Syntax** — когда нужно изменить конкретный канал цвета (светлоту, насыщенность, оттенок), сохранив остальные параметры интенсивности неизменными. Хорошо подходит для точных, предсказуемых состояний вроде hover/active, где интенсивность бренд-цвета должна остаться узнаваемой.
* **`color-mix()`** — когда нужно смешать цвет с другим конкретным цветом (белым, чёрным, поверхностью, акцентом). Результат всегда тяготеет к цвету, с которым идёт смешивание, по всем каналам сразу — это осознанный визуальный эффект, а не побочный.

Выбирайте инструмент по желаемому результату, а не по «современности» синтаксиса — оба метода одинаково актуальны и присутствуют в спецификации CSS Color Module Level 5.




**4. Для смешивания нескольких цветов используйте `color-mix()`**

```css
/* ✅ Рекомендуется */
background: color-mix(in oklch, var(--surface), var(--brand) 20%);

/* ❌ Устаревает */
background: rgba(37, 99, 235, 0.2);
```

**5. Светлую и тёмную темы описывайте через `light-dark()`**

```css
/* ✅ Рекомендуется */
--surface: light-dark(white, #1a1a1a);

/* ❌ Устаревает */
@media (prefers-color-scheme: dark) {
  --surface: #1a1a1a;
}
```

**6. Проверяйте поддержку новых возможностей через `@supports`**

```css
/* ✅ Рекомендуется */
@supports (color: contrast-color(white)) {
  color: contrast-color(var(--surface));
}
@supports not (color: contrast-color(white)) {
  color: white;
}
```

**7. Стройте дизайн-систему вокруг небольшого числа базовых токенов**

```text
Хорошая архитектура:
  ↓
5-10 базовых цветов
  ↓
Все остальные — вычисляемые
  ↓
Плохая архитектура:
  ↓
50+ цветовых переменных
  ↓
Каждая — отдельное значение
```

## 13.9 Итоги главы

1. **Цвет как вычисляемое значение** — CSS хранит правила получения цвета, а не сами оттенки

2. **`color-mix()`** — декларативное смешивание цветов в любом пространстве

3. **Relative Color Syntax** — изменение отдельных каналов существующего цвета; это не «более современная» альтернатива `color-mix()`, а инструмент для другой задачи — см. уточнение в разделе 13.8

4. **Алгоритмические палитры** — компактная, предсказуемая, легко адаптируемая система

5. **`light-dark()`** — разделение логики выбора цвета и темы оформления

6. **`contrast-color()`** — автоматический выбор контрастного текста (Baseline Newly Available с апреля 2026 года)

7. **Архитектура дизайн-систем** — Brand → Relative → color-mix() → light-dark() → contrast-color()

8. **Практические правила:** OKLCH, вычисление вместо хранения, осознанный выбор между Relative Color Syntax и `color-mix()`, проверка поддержки

---

**Главная мысль:** Развитие CSS Color знаменует переход от статических палитр к вычисляемым цветовым системам. Если ещё несколько лет назад браузер лишь отображал заранее подготовленные значения, то сегодня он способен самостоятельно смешивать цвета, изменять их параметры, адаптировать оформление под тему интерфейса и участвовать в обеспечении доступности. Вместе с перцептивными пространствами OKLab и OKLCH это превращает CSS в полноценную платформу для построения алгоритмических дизайн-систем, где ключевую роль играют не отдельные цветовые значения, а правила их получения.
