# Предисловие

# CSS больше не язык оформления: рождение новой платформы

На протяжении почти тридцати лет CSS воспринимался как вспомогательный язык оформления HTML-документов. Его роль казалась очевидной: определить цвета, шрифты, отступы, размеры и расположение элементов на странице. Логика приложения оставалась за JavaScript, а архитектура интерфейсов строилась вокруг библиотек и фреймворков.

Однако к 2026 году эта картина полностью изменилась.

Современный CSS перестал быть исключительно системой оформления. Сегодня это самостоятельная декларативная платформа, обладающая собственной архитектурой, системой типов, вычислениями, реактивностью, анимацией, механизмами адаптации интерфейсов и тесной интеграцией с движком браузера.

Если раньше разработчик задавал вопрос:

> «Как оформить этот элемент?»

то сегодня всё чаще возникает другой вопрос:

> **«Может ли эту задачу решить сам CSS без JavaScript?»**

Во многих случаях ответ оказывается положительным.

Именно этой трансформации посвящена книга **Modern CSS 2026**.

---

# Почему CSS изменился

За последние несколько лет изменился не только сам язык CSS — изменилась вся философия развития Web Platform.

Браузеры перестали восприниматься как пассивные исполнители инструкций JavaScript. Напротив, всё больше логики переносится непосредственно в платформу. HTML становится декларативным API браузера, JavaScript постепенно превращается в язык интеграции, а CSS получает новые обязанности, которые ещё недавно считались невозможными без программирования.

Эта эволюция обусловлена несколькими фундаментальными причинами.

Во-первых, современные интерфейсы стали значительно сложнее. Адаптивный дизайн уступил место компонентным системам, где каждый компонент должен самостоятельно реагировать на своё окружение, а не только на размеры окна браузера.

Во-вторых, требования к производительности стали существенно выше. Любая дополнительная строка JavaScript увеличивает размер загружаемого приложения, время его анализа, компиляции и выполнения. Поэтому разработчики браузеров стремятся переносить всё больше вычислений непосредственно в нативные механизмы движков Blink, WebKit и Gecko.

В-третьих, современный веб постепенно становится декларативным. Вместо описания последовательности действий разработчик всё чаще описывает желаемое состояние интерфейса, предоставляя браузеру возможность самостоятельно выбирать наиболее эффективный способ его реализации.

Именно поэтому новые возможности CSS появляются не как отдельные свойства, а как новые уровни абстракции всей платформы.

---

# CSS больше не развивается версиями

Одним из наиболее заметных изменений последних лет стало исчезновение привычной модели развития языка.

Когда-то существовали CSS1, CSS2 и CSS2.1. Многие разработчики десятилетиями ожидали появления «CSS4».

Но CSS4 никогда не появится.

Современный CSS развивается как набор независимых модулей, каждый из которых имеет собственный жизненный цикл.

Например:

* CSS Grid Layout Module Level 2;
* CSS Color Module Level 5;
* CSS Cascade Module Level 6;
* CSS Anchor Positioning;
* CSS View Transitions;
* CSS Scroll-driven Animations.

Каждый модуль развивается независимо, получает собственные уровни зрелости и внедряется браузерами по мере готовности.

Именно поэтому сегодня невозможно сказать:

> «Я изучил CSS полностью.»

Можно изучать только отдельные части постоянно развивающейся платформы.

---

# CSS становится частью браузерного движка

Самое важное изменение произошло не в синтаксисе языка.

Изменилась сама архитектура выполнения CSS.

Если раньше CSS воспринимался как набор деклараций для оформления элементов, то теперь он участвует практически во всех стадиях работы браузера:

* построении дерева рендеринга;
* вычислении каскада;
* алгоритмах раскладки;
* определении размеров компонентов;
* вычислении контейнерных запросов;
* анимации;
* композиции слоёв;
* GPU-композитинге;
* оптимизации производительности.

Современный CSS тесно интегрирован практически со всеми подсистемами браузера.

Именно поэтому понимание внутренней архитектуры платформы становится важнее запоминания отдельных свойств.

---

# От языка стилей к декларативному программированию

Ещё несколько лет назад многие задачи считались исключительно областью JavaScript.

Сегодня значительная часть из них может быть решена средствами CSS.

Например:

* адаптация компонентов через **Container Queries**;
* условная логика через **`:has()`**;
* сложные математические вычисления через `calc()`, `min()`, `max()` и `clamp()`;
* каскадная архитектура посредством **Cascade Layers**;
* управление областью действия стилей через **@scope**;
* вложенность правил (**CSS Nesting**);
* анимации, синхронизированные с прокруткой (**Scroll-driven Animations**);
* плавные переходы между состояниями интерфейса (**View Transition API**);
* позиционирование элементов относительно других компонентов (**CSS Anchor Positioning**).

Во многих случаях JavaScript перестал быть обязательным.

CSS постепенно становится языком описания поведения пользовательского интерфейса.

---

# Почему Sass уже перестал быть обязательным

Почти двадцать лет препроцессоры существовали потому, что самого CSS было недостаточно.

Sass предоставлял:

* переменные;
* вложенность;
* функции;
* миксины;
* математические операции;
* повторное использование кода.

Но постепенно сама платформа начала поглощать лучшие идеи препроцессоров.

Сегодня нативный CSS уже включает:

* Custom Properties;
* CSS Nesting;
* современные математические функции;
* каскадные слои;
* регистрацию пользовательских свойств через `@property` (Baseline).

Кроме того, платформа начала осваивать и саму идею пользовательских функций — но пока неравномерно. Правило `@function` из спецификации CSS Custom Functions and Mixins Module уже реализовано в Chrome и Edge (начиная с версии 139), однако остаётся статусом Limited availability: Firefox и Safari пока его не поддерживают, и до Baseline эта возможность не дотягивает. Смежные конструкции того же модуля — `@mixin`, `@apply`, `@contents` и `@env`, отвечающие за переиспользуемые блоки CSS с аргументами, — на момент написания книги не поддерживаются ни одним браузером и существуют только на уровне спецификации.

Даже с учётом этой неравномерности сама тенденция важна: то, что раньше было исключительно территорией Sass, постепенно становится частью нативной платформы.

Однако самое важное отличие заключается в другом.

Возможности CSS работают **во время выполнения приложения**, а не только на этапе сборки.

CSS получает доступ к информации, которую никогда не мог видеть Sass:

* размер контейнера;
* состояние элементов;
* предпочтения пользователя;
* цветовую схему;
* режим уменьшенной анимации;
* положение элемента относительно области просмотра;
* динамическое изменение пользовательских переменных.

Именно это превращает CSS в полноценную среду выполнения.

# Houdini — открытие внутренней архитектуры CSS

Одним из наиболее амбициозных направлений развития платформы стал проект **Houdini**.

Его цель заключается в том, чтобы предоставить разработчикам доступ к внутренним механизмам браузера, которые раньше были полностью закрыты.

С помощью Houdini разработчики получают возможность:

* регистрировать типизированные CSS-свойства через `@property` — эта часть Houdini уже достигла статуса Baseline и одинаково работает во всех современных браузерах;
* создавать собственные алгоритмы рисования через Paint API — на практике эта возможность остаётся Limited availability и по-настоящему стабильно работает только в браузерах на Chromium;
* работать с CSS как с типизированными объектами через Typed OM;
* в перспективе — реализовывать пользовательские алгоритмы раскладки через Layout API, который по-прежнему носит экспериментальный характер и не имеет широкой поддержки браузеров.

Таким образом, Houdini — это не единый монолитный набор технологий одного уровня зрелости, а спектр возможностей: от уже стандартизированных и повсеместно доступных до всё ещё экспериментальных и ограниченных одним браузерным движком. Тем не менее общее направление остаётся прежним: Houdini превращает CSS из закрытого языка деклараций в расширяемую программную платформу.

# Baseline — новый способ разработки

Одним из важнейших изменений последних лет стала концепция **Baseline**.

Раньше разработчики постоянно задавались вопросом:

> «Можно ли уже использовать эту возможность?»

Теперь ответ даёт сама платформа.

Baseline определяет набор возможностей, гарантированно поддерживаемых всеми современными браузерами.

Это меняет сам процесс разработки.

Вместо бесконечных проверок совместимости разработчик проектирует приложение, исходя из возможностей современной Web Platform.

Именно поэтому книга **Modern CSS 2026** уделяет большое внимание статусу Baseline каждой рассматриваемой технологии.

---

# Почему эта книга называется «Modern CSS 2026»

Эта книга — не справочник по свойствам CSS.

Она посвящена современной архитектуре платформы.

Мы будем рассматривать CSS не как набор отдельных возможностей, а как взаимосвязанную систему, включающую:

* современный каскад;
* архитектуру компонентов;
* вычислительную модель браузера;
* алгоритмы раскладки;
* реактивность;
* производительность;
* анимацию;
* взаимодействие с HTML;
* интеграцию с современным JavaScript.

Многие темы книги появились совсем недавно или только достигли статуса Baseline. Некоторые ещё продолжают развиваться, но уже сегодня меняют подход к проектированию пользовательских интерфейсов.

Понимание этих изменений позволяет создавать приложения, которые становятся быстрее, проще, надёжнее и легче в сопровождении.
