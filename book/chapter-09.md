# Глава 9. `:has()` и реляционная модель CSS

> **Цель главы:** показать, что `:has()` — не просто долгожданный «родительский селектор», а начало новой модели CSS, где стили определяются отношениями между элементами, а не только их положением в дереве DOM.

---

## 9.1 От однонаправленных селекторов к реляционной модели

### Историческое ограничение CSS

До появления **Selectors Level 4** CSS оставался языком однонаправленного поиска. Разработчик мог:

```text
Выбирать потомков
  ↓
div p { ... }
  ↓
Выбирать соседей
  ↓
h1 + p { ... }
  ↓
Выбирать следующий элемент
  ↓
h1 ~ p { ... }
  ↓
Выбирать по состоянию
  ↓
input:checked { ... }
```

Но CSS **не мог ответить на вопросы:**

```text
"Есть ли внутри этого элемента изображение?"
  ↓
"Является ли этот элемент частью формы?"
  ↓
"Содержит ли карточка кнопку?"
  ↓
"Есть ли после этого заголовка абзац?"
```

### Почему это было проблемой

Огромное количество логики приходилось переносить в JavaScript:

```javascript
// Добавлять класс при наличии изображения
if (card.querySelector('img')) {
  card.classList.add('has-image');
}

// Менять класс родителя через closest()
const parent = button.closest('.card');
parent.classList.add('has-button');

// Переключать состояние карточки вручную
card.addEventListener('mouseenter', () => {
  card.classList.add('hover');
});

// Перестраивать меню после изменения DOM
menu.querySelectorAll('li').forEach(item => {
  if (item.querySelector('ul')) {
    item.classList.add('has-submenu');
  }
});
```

### Решение: реляционный псевдокласс

Именно эту проблему решил `:has()`.

Главная идея состоит не в выборе родителя. Главная идея —

> **селектор теперь способен принимать решение на основании отношений между элементами DOM.**

Именно поэтому спецификация называет `:has()` **relational pseudo-class**, а не parent selector.

```text
CSS до :has()
  ↓
однонаправленные селекторы (вниз по дереву)
  ↓
CSS с :has()
  ↓
реляционные селекторы (любое направление)
```

**Что изменилось:**

| Аспект | До :has() | После :has() |
|--------|-----------|--------------|
| Направление | Только вниз (потомки) | Любое (родители, соседи, потомки) |
| Логика | "Что внутри элемента?" | "Что связано с элементом?" |
| Зависимость от JS | Высокая | Низкая |
| Компоненты | Требуют модификаторов | Самодостаточны |

## 9.2 Как браузер вычисляет `:has()`

### Принцип работы

Очень важно понимать принцип работы. CSS никогда не начинает поиск "изнутри". Браузер по-прежнему начинает с элемента, который проверяет.

```css
.card:has(img)
```

означает буквально:

> "Для каждой `.card` проверить, существует ли внутри неё `img`."

```text
Алгоритм браузера:
  ↓
1. Найти все элементы .card
  ↓
2. Для каждого .card проверить, есть ли внутри img
  ↓
3. Если есть — применить стили
  ↓
4. Если нет — не применять
```

### Отличие от DOM API

Это отличается от DOM API. JavaScript делает наоборот:

```javascript
// JavaScript — сначала находит img, затем поднимается вверх
const img = document.querySelector('img');
const card = img.closest('.card');
```

**Важно:** `:has()` — не обход дерева, а часть алгоритма сопоставления селекторов движка браузера.

### Почему это важно для производительности

```text
DOM API (JavaScript)
  ↓
начинает с img
  ↓
поднимается вверх через parentElement
  ↓
обходит дерево
  ↓
медленно при большом DOM
  ↓
CSS :has()
  ↓
начинает с .card
  ↓
проверяет наличие img внутри
  ↓
оптимизированный алгоритм браузера
  ↓
быстро
```

Это объясняет, почему современные браузеры смогли сделать `:has()` достаточно быстрым.

### Инвалидация стилей

При изменении DOM браузер должен перепроверить все `:has()`-селекторы:

```text
Изменение DOM
  ↓
Браузер проверяет, какие элементы изменились
  ↓
Пересчитывает :has() для затронутых элементов
  ↓
Применяет или удаляет стили
  ↓
Обновляет отображение
```

Современные движки используют оптимизированные алгоритмы инвалидации, которые минимизируют пересчёты.

## 9.3 Не только родительский селектор

### Множество применений

Самый известный пример:

```css
.card:has(img)
```

но он далеко не самый интересный. `:has()` способен анализировать практически любые отношения между элементами.

### Проверка наличия элементов

```css
/* Карточка с формой */
.card:has(form) {
  border-color: var(--color-primary);
}

/* Карточка с кнопкой */
.card:has(button) {
  cursor: pointer;
}

/* Карточка с видео */
.card:has(video) {
  padding: 0;
  overflow: hidden;
}

/* Карточка с галереей */
.card:has(.gallery) {
  background: var(--color-surface);
}
```

### Реакция на состояния

```css
/* Группа формы с ошибкой */
.form-group:has(:invalid) {
  border-color: var(--color-danger);
}

/* Группа формы с заполненным полем */
.form-group:has(input:not(:placeholder-shown)) {
  background: var(--color-success-light);
}

/* Задача с активным чекбоксом */
.todo:has(input:checked) {
  text-decoration: line-through;
  opacity: 0.6;
}

/* Меню с открытым подменю */
.menu-item:has(details[open]) {
  background: var(--color-hover);
}

/* Поле в фокусе */
.field:has(:focus-visible) {
  box-shadow: var(--shadow-focus);
}
```

### Реакция на атрибуты

```css
/* Секция с изображением */
.section:has([data-image]) {
  padding: 0;
}

/* Статья с featured-меткой */
.article:has([data-featured]) {
  border-left: 4px solid var(--color-primary);
}

/* Карточка с тегами */
.card:has([data-tags]) .card-footer {
  display: block;
}
```

### Проверка отношений

```css
/* Заголовок с последующим абзацем */
h1:has(+ p) {
  margin-bottom: 0.25rem;
}

/* Секция с последующей секцией */
section:has(+ section) {
  border-bottom: 1px solid var(--border-color);
}

/* Метка перед невалидным полем */
label:has(+ input:invalid) {
  color: var(--color-danger);
}

/* Статья перед статьёй */
article:has(+ article) {
  border-bottom: 1px solid var(--border-color);
}
```

### Фактический итог

CSS получил возможность реагировать на состояние внутренних элементов **без единой строки JavaScript**.

```text
Раньше:
  ↓
JavaScript проверяет наличие элементов
  ↓
Добавляет/удаляет классы
  ↓
CSS стилизует по классам
  ↓
Сейчас:
  ↓
CSS сам проверяет наличие элементов
  ↓
Применяет стили напрямую
  ↓
Без JavaScript
```

## 9.4 Селектор предыдущего элемента

### Новая возможность типографики

Именно эта возможность изменила типографику современного CSS.

```css
h1:has(+ h2)
```

означает:

> "Выбрать `h1`, если сразу после него расположен `h2`."

Это впервые позволило стилизовать **предыдущий** элемент.

### Типографические паттерны

```css
/* Заголовок с подзаголовком */
h1:has(+ h2) {
  margin-bottom: 0.25rem;
}

/* Заголовок без подзаголовка */
h1:not(:has(+ h2)) {
  margin-bottom: 1.5rem;
}

/* Абзац перед списком */
p:has(+ ul) {
  margin-bottom: 0.5rem;
}

/* Разделитель между статьями */
article:has(+ article) {
  border-bottom: 2px solid var(--border-color);
  padding-bottom: var(--space-lg);
}

/* Первый элемент в группе */
.item:has(+ .item) {
  border-bottom: 1px solid var(--border-color);
}
```

### Сложные цепочки

```css
/* Заголовок через один элемент */
h1:has(+ * + h2) {
  margin-bottom: 0.25rem;
}

/* Метка перед полем с ошибкой */
label:has(+ input:invalid) {
  color: var(--color-danger);
  font-weight: bold;
}

/* Элемент перед активным элементом */
.nav-item:has(+ .nav-item.active) {
  border-right: 1px solid var(--color-primary);
}
```

### Почему это важно

```text
Раньше:
  ↓
Нельзя стилизовать предыдущий элемент
  ↓
Нужно менять разметку
  ↓
Или использовать JavaScript
  ↓
Сейчас:
  ↓
Можно стилизовать любой элемент
  ↓
На основе любых отношений
  ↓
Чистый CSS
```

## 9.5 Новый уровень компонентной архитектуры

### Самодостаточные компоненты

Наиболее серьёзные последствия `:has()` проявились именно в компонентном CSS. Теперь компонент способен самостоятельно определять собственную структуру.

```css
/* Карточка с изображением */
.card:has(img) {
  padding: 0;
  overflow: hidden;
  border-radius: var(--radius-lg);
}

.card:has(img) .card-content {
  padding: var(--space-md);
}

/* Карточка с видео */
.card:has(video) .card-content {
  padding: var(--space-sm);
}

/* Карточка с кнопкой */
.card:has(.btn) {
  border: 2px solid var(--color-primary);
}

/* Карточка с featured-меткой */
.card:has([data-featured]) {
  border-color: var(--color-warning);
  box-shadow: var(--shadow-lg);
}
```

### Без модификаторов

```html
<!-- Раньше — нужно добавлять классы -->
<div class="card card--has-image">
  <img src="..." alt="">
  <div class="card-content">...</div>
</div>

<div class="card card--has-video">
  <video src="..."></video>
  <div class="card-content">...</div>
</div>

<!-- Теперь — чистый HTML -->
<div class="card">
  <img src="..." alt="">
  <div class="card-content">...</div>
</div>

<div class="card">
  <video src="..."></video>
  <div class="card-content">...</div>
</div>
```

**Важное следствие:** HTML перестаёт дублировать информацию, которая уже содержится в DOM.

### Формы

```css
/* Поле с ошибкой после взаимодействия */
.form-group:has(input:user-invalid) {
  border-color: var(--color-danger);
}

.form-group:has(input:user-invalid) .error-message {
  display: block;
}

/* Поле с успешной валидацией */
.form-group:has(input:user-valid) {
  border-color: var(--color-success);
}

.form-group:has(input:user-valid) .success-message {
  display: block;
}

/* Группа с заполненными полями */
.form-section:has(input:not(:placeholder-shown)) {
  background: var(--color-surface);
}
```

### Навигация

```css
/* Активный пункт меню */
.nav-item:has(.active) {
  background: var(--color-primary);
  color: white;
}

/* Пункт с подменю */
.nav-item:has(ul) {
  position: relative;
}

.nav-item:has(ul)::after {
  content: '▼';
  margin-left: var(--space-xs);
}

/* Пункт с открытым подменю */
.nav-item:has(ul[open]) {
  background: var(--color-hover);
}
```

### Карточки

```css
/* Карточка с изображением и кнопкой */
.card:has(img):has(.btn) {
  border: 2px solid var(--color-primary);
}

/* Карточка с несколькими изображениями */
.card:has(img:nth-child(2)) {
  display: grid;
  grid-template-columns: 1fr 1fr;
}

/* Карточка с длинным текстом */
.card:has(p:not(:first-child)) .card-content {
  overflow: auto;
}
```

## 9.6 Совместная работа с Container Queries

### Мощная композиция

Наиболее интересные архитектуры появляются при объединении:

- `:has()` — анализ структуры
- Container Queries — анализ размера
- Custom Properties — динамические значения

### Пример: полностью декларативный компонент

```css
/* Компонент сам определяет свою структуру */
.card-container {
  container-type: inline-size;
  container-name: card;
}

.card {
  /* Базовые стили */
  padding: var(--space-md);
  background: var(--color-surface);
  border-radius: var(--radius-lg);
}

/* Есть изображение → меняем layout */
.card:has(img) {
  padding: 0;
  overflow: hidden;
}

.card:has(img) .card-content {
  padding: var(--space-md);
}

/* Есть кнопка → добавляем акцент */
.card:has(.btn) {
  border: 2px solid var(--color-primary);
}

/* Адаптация к размеру контейнера */
@container card (max-width: 400px) {
  .card:has(img) {
    display: grid;
    grid-template-columns: 1fr;
  }
}

@container card (min-width: 401px) {
  .card:has(img) {
    display: grid;
    grid-template-columns: 1fr 2fr;
  }
}

/* Меняем тему через Custom Properties */
.card:has([data-featured]) {
  --card-bg: var(--color-featured);
  --card-border: var(--color-primary);
}
```

### Пример: сложная композиция

```css
/* 1. Карточка определяет своё содержимое */
.product-card {
  container-type: inline-size;
  container-name: product;
}

/* 2. Реакция на наличие изображения */
.product-card:has(img) .product-info {
  padding: var(--space-md);
}

/* 3. Реакция на наличие скидки */
.product-card:has(.badge-sale) {
  border-color: var(--color-danger);
}

/* 4. Реакция на размер контейнера */
@container product (max-width: 400px) {
  .product-card:has(img) {
    flex-direction: column;
  }
}

@container product (min-width: 401px) {
  .product-card:has(img) {
    display: grid;
    grid-template-columns: 1fr 2fr;
  }
}

/* 5. Реакция на тему */
.product-card:has([data-theme="dark"]) {
  --card-bg: var(--color-dark);
  --card-text: var(--color-light);
}
```

### Результат

```text
Компонент без JavaScript
  ↓
Анализирует свою структуру (:has())
  ↓
Анализирует свой размер (Container Queries)
  ↓
Анализирует своё окружение (Custom Properties)
  ↓
Полностью адаптивный и самодостаточный
```

Именно такая композиция считается современным направлением развития CSS.

## 9.7 Ограничения спецификации

### Что нельзя делать с `:has()`

Несмотря на мощь `:has()`, спецификация сознательно вводит ограничения.

**1. Нельзя вкладывать `:has()` друг в друга**

```css
/* ❌ Не работает — вложенный :has() */
.card:has(img:has(.badge)) {
  /* Не сработает */
}

/* ✅ Работает — плоская структура */
.card:has(img .badge) {
  /* Сработает */
}
```

**2. Нельзя использовать псевдоэлементы**

```css
/* ❌ Не работает — псевдоэлемент */
.card:has(::before) {
  /* Не сработает */
}

/* ✅ Работает — проверка наличия атрибута */
.card:has([data-before]) {
  /* Сработает */
}
```

**3. Нельзя использовать `:has()` как якорь псевдоэлемента**

```css
/* ❌ Не работает — :has() в псевдоэлементе */
.card::before:has(img) {
  /* Не сработает */
}

/* ✅ Работает — проверка на самом элементе */
.card:has(img)::before {
  /* Сработает */
}
```

### Forgiving Selector List

Аргументы `:has()` являются **forgiving selector list** — ошибочный селектор внутри списка игнорируется, не ломая всё правило:

```css
/* Ошибка внутри списка не ломает правило */
.card:has(img, .invalid-selector, .btn) {
  /* img и .btn работают, .invalid-selector игнорируется */
}
```

**Преимущества:**
- Облегчает Progressive Enhancement
- Позволяет использовать новые селекторы
- Не ломает старые браузеры

**Недостатки:**
- Может скрывать случайные опечатки
- Сложнее отлаживать

## 9.8 Производительность

### История

Появление `:has()` откладывалось почти двадцать лет именно из-за производительности. Ранние реализации были слишком медленными для реальных проектов.

### Современное состояние

Современные движки браузеров решили эту проблему за счёт новой системы инвалидации стилей:

```text
Старый подход:
  ↓
При изменении DOM — пересчитать все селекторы
  ↓
Медленно при большом DOM
  ↓
Новый подход:
  ↓
Отслеживать, какие элементы изменились
  ↓
Пересчитывать только затронутые селекторы
  ↓
Быстро
```

### Хорошие практики

**Лучше:**
```css
.card:has(> img) { /* Только прямые потомки */ }
```

**Чем:**
```css
.card:has(img) { /* Все потомки — шире область */ }
```

**Лучше:**
```css
.menu:has(+ .submenu) { /* Только соседи */ }
```

**Чем:**
```css
.menu:has(.submenu) { /* Поиск по всему поддереву */ }
```

### Главное правило

> **Чем меньше область поиска внутри `:has()`, тем меньше работы выполняет движок браузера.**

```text
.card:has(> img) → проверяет только прямых потомков
  ↓
.card:has(img) → проверяет всех потомков
  ↓
.card:has(div img) → проверяет все вложенные div и их потомков
```

### Рекомендации по производительности

1. Используйте прямой потомок (`>`) где возможно
2. Ограничивайте глубину поиска
3. Не комбинируйте множество `:has()` на одном элементе
4. Используйте `:has()` для компонентов, а не для всего документа
5. Тестируйте производительность на больших DOM-деревьях

## 9.9 Архитектурные рекомендации

### Когда использовать `:has()`

Сегодня `:has()` стоит рассматривать как инструмент высокого уровня. Он особенно полезен для:

- **Компонентных библиотек** — компоненты самодостаточны
- **Дизайн-систем** — единообразное поведение
- **Сложных форм** — валидация и состояния
- **Адаптивной типографики** — стилизация на основе структуры
- **Карточек и плиток** — адаптация к содержимому
- **Навигации** — активные и вложенные пункты
- **Декларативных состояний интерфейса** — без JavaScript

### Когда не использовать `:has()`

- Как замену JavaScript для сложной логики
- Для массового применения на всех элементах
- В критических по производительности участках
- Для проверки большого количества вложений

### Комбинация с другими инструментами

Наиболее сильный эффект появляется тогда, когда `:has()` становится частью общей архитектуры вместе с:

```text
@layer
  ↓
архитектурное управление приоритетами
  ↓
@scope
  ↓
изоляция компонентов
  ↓
Container Queries
  ↓
адаптация к размеру
  ↓
Design Tokens
  ↓
```

### Практические правила

**1. Используйте `:has()` для отношений, а не для состояний**

```css
/* ✅ Хорошо — отношения */
.card:has(img) { ... }

/* ❌ Плохо — состояния (есть псевдоклассы) */
.card:has(:hover) { ... } /* Используйте .card:hover */
```

**2. Комбинируйте с другими селекторами**

```css
/* ✅ Хорошо */
.card:has(> img):hover {
  transform: scale(1.02);
}

/* ❌ Плохо — слишком сложно */
.card:has(> img:not(.placeholder)):not(:has(.btn)) {
  /* Слишком сложно для понимания */
}
```

**3. Используйте для создания контрактов компонентов**

```css
/* Компонент обещает: если есть img — меняем layout */
.card:has(img) {
  padding: 0;
}

/* Компонент обещает: если есть кнопка — добавляем акцент */
.card:has(.btn) {
  border-color: var(--color-primary);
}
```

## 9.10 Итоги главы

1. **`:has()` — не "родительский селектор"** — это первый полноценный **реляционный селектор CSS**

2. **Он позволяет принимать решения на основании структуры документа**, а не только положения элемента

3. **Движок браузера вычисляет `:has()` от элемента к потомкам** — это не обход дерева, а часть алгоритма сопоставления селекторов

4. **`:has()` может анализировать практически любые отношения** — потомки, соседи, состояния, атрибуты

5. **Появилась возможность стилизовать предыдущий элемент** — `h1:has(+ h2)` и подобные конструкции

6. **Компоненты стали самодостаточными** — HTML перестаёт дублировать информацию из DOM

7. **Комбинация с Container Queries и Custom Properties** создаёт полностью декларативные компоненты

8. **Спецификация сознательно ограничивает `:has()`** — нет вложенности, нет псевдоэлементов

9. **Производительность решена через новую систему инвалидации** — но хорошие практики остаются важными

10. **`:has()` — инструмент высокого уровня** для компонентных библиотек, дизайн-систем и сложных форм

---

**Главная мысль:** `:has()` — это не просто новый селектор, а фундаментальное изменение в философии CSS. Впервые разработчик получил возможность описывать стили на основе **отношений** между элементами, а не только их положения в DOM. В сочетании с Container Queries, Custom Properties и архитектурными инструментами (`@layer`, `@scope`) это открывает путь к полностью декларативным, самодостаточным компонентам, которые не требуют JavaScript для адаптации к структуре и контексту.
